# V3 阶段 0b 执行入口

本实验只改变训练样本的频率。Ridge R02 和 LightGBM 回归 L03 各在 W1–W4 拟合一次，训练使用原 33 个特征，评价沿用 0a 五日截面。参数和样本资格见[冻结配置](../config/density_0b.json)。0b 比较每日横截面预测 IC。

## 核验和运行

在 Project 目录使用项目虚拟环境运行。默认命令只核对公开配置，输出 8 个任务；第二条额外读取开发期输入，核对两个基线的五日候选键、交易资格、有效标签键和值，并从原预测复算逐日 IC。两条都不创建正式运行目录。

```powershell
.\.venv\Scripts\python.exe scripts/density_v3.py
.\.venv\Scripts\python.exe scripts/density_v3.py --check-inputs
```

正式运行的显式开关为 `--execute`。入口先核对准备阶段的来源清单、0a 账本、软件版本、快照及对应预测文件，再检查全部窗口的评价样本。训练读取仅投影原 21 列和背景 12 列；标签按各窗口训练或评价截止日分别读取，要求终点晚于信号日、状态合格、收益有限。截尾、填补和标准化按窗口训练行重新估计。对树模型，横截面排名使用当日合格股票，随后才按标签资格选训练行。

每个任务在 `outputs/v3_density_0b/` 下保存模型、预处理状态、评价期五日候选的预测、与对应 0a 基线的逐日配对 IC、训练和评价覆盖数及最大标签日期。八项均完成后生成 `comparison.json`，含每个模型的四窗口等权均值。逐股产物留在本地。

## 预算与恢复

账本为 `fit_ledger.json`。先原子落盘 `running` 再进入单次拟合操作。预算按已预占的不同任务计算。正常完成后记录产物哈希，异常或可捕获的中断记录 `failed`；进程被强制终止可能留下 `running` 和写锁。三种状态都占一次预算。

只有在**两个任务之间**暂停、既有任务均已完成且哈希有效时，`--execute --resume` 才能跳过已经完成的任务并继续。变更输入或环境、产物损坏、未决预占或失败都会阻止恢复。遇到残留写锁先保留现场，核对进程与账本。普通执行拒绝覆盖已有目录。

## 本次验收

真实开发期只做输入核验。W1–W4 的有效评价行数依次为 24,403、24,427、24,427、24,438，两个配对基线逐日 IC 均复算通过。合成测试用临时 Parquet 和虚构股票序列走通真实 Ridge 和 LightGBM 的拟合、保存及汇总路径，另注入错误检查训练标签跨年、评价键被等量替换、窗口重叠、失败、强制退出、恢复和第九次预占。运行 `python -m pytest -q tests/test_density_v3.py` 可重复合成验收。正式拟合仍为零。
